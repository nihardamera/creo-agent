- Deps added: pydantic 2.14.2, PyYAML 6.0.3 (+ types-PyYAML).

Decisions made in M1 (M2 must implement them; the labels assume them):
- Node order: ingest → screen → dedupe → ticket → gather_context →
  select_runbook → diagnostics → classify → decide_wait → (wait → recheck)×n
  → propose_fix → approval → execute → verify → resolve | escalate → finalize.
- Ingest ends a run early for: duplicate event id (webhook retry), stale
  `$DATE`, Warn/No Data transitions, Recovered with no open run.
- Screen (deterministic) flags: injection-like text, fake approvals,
  non-schema tag keys, tag values that aren't safe identifiers, foreign URLs.
  Flagged → escalate to security-ops without a ticket-linking step.
- select_runbook: tags pick the runbook; a missing `runbook:` tag falls back
  to the single runbook matching (monitor_type, inventory role); two runbook
  tags, a type mismatch or a role the runbook doesn't cover → escalate (noc);
  a tag contradicting inventory (role, tier, a service the host doesn't run)
  → escalate (security-ops).
- diagnostics output is screened too (indirect injection) before classify.
- A Recovered webhook during a wait wakes the run → resolve without recheck.
- Tier-0 hosts: wait and recheck, never propose a fix.
- Eval runs each case in isolation; setup runs get no approval answers.

Gate (2026-11-01): passed. Corrections given on: runbook tag is routing,
not leakage; the manifest hash is integrity, not a guard; no near-duplicate
test exists; planted-defect tests now assert the specific rule.

Open questions:
- Live replayer (compose demo) vs. isolation: cases share hosts, so replaying
  many cases into one agent can cross-dedupe. Option: give the replayer a
  per-case monitor-id namespace, or only replay cases in isolation-safe order.
- Classify is solvable from typed fields by design; M3 should report a

- `unicode` cases all end `resolved` (spurious correlation); mix in

- OLLAMA_MODEL default in creo/settings.py ("qwen3:4b") is a placeholder;
  check the current Ollama library and pick a 3–4B model before using it.
- The live replayer can cross-correlate concurrent cases that share a site
  and service (incident key); eval runs cases in isolation, so M3 is
